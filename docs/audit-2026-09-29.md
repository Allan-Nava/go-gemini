## 0. Verifica funzionale (2026-09-29)

Prova dal vivo con il client resty dell'SDK (`NewGoGemini`, header di default, nessun cookie), in una
copia del repo fuori dall'albero tracciato:

| Prova | Esito |
|---|---|
| `GetAnswer()` | `nil`, nessuna richiesta inviata → **l'SDK non funziona** |
| `GET https://bard.google.com/` | `301` → `https://gemini.google.com/`, 200, pagina da ~850 KB |
| token `SNlM0e` nella pagina (regex dell'SDK) | **assente** senza sessione: `getSnim0e()` non potrebbe estrarlo |
| `POST …/BardFrontendService/StreamGenerate` con `f.req` + `at=""` | **200**, risposta generata (`)]}'` + `wrb.fr`); modello riportato `3.5 Flash-Lite` |

Conclusione: il repo non produce risposte, ma **l'endpoint su cui era costruito risponde ancora, anche
senza cookie** (modalità anonima di Gemini). Il body contiene anche la **località stimata dall'IP del
chiamante**: non va mai loggato né committato. La correzione al §1 qui sotto sostituisce la versione
precedente di questo audit, che dava l'endpoint per dismesso.

## Findings

### 1. [CRITICO] L'API target non è documentata — serve una decisione

Il client è costruito sul web client di Bard: cookie di sessione `__Secure-1PSID` copiato dal
browser, token `SNlM0e` estratto dall'HTML, POST a
`/_/BardChatUi/data/assistant.lamda.BardFrontendService/StreamGenerate`. Bard è diventato Gemini
a febbraio 2024; gli endpoint rispondono ancora (§0), ma loro e il formato `f.req` non sono documentati,
possono cambiare senza preavviso e il loro uso automatizzato è fuori dai termini di servizio Google. Un cookie di sessione dà inoltre
accesso all'intero account Google di chi lo copia.

Opzioni:

| | A — API ufficiale Gemini | B — wrapper di `google.golang.org/genai` | C — scraping web client |
|---|---|---|---|
| Auth | API key (`GEMINI_API_KEY`) | API key / Vertex | nessuna (anonimo) o cookie di sessione |
| Stabilità | versionata | versionata | funziona oggi, nessuna garanzia |
| Valore del repo | client leggero, poche dipendenze | helper sopra l'SDK ufficiale | unico, ma fragile |
| Rischio | basso | basso | ToS + esposizione account |

Raccomandazione: **A** (REST `generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`),
mantenendo il nome `go-gemini`. Il nome del modulo resta valido; cambiano costanti, configurazione
e il flusso di autenticazione.

### 2. [ALTO] Nessuna funzionalità reale

- `GetAnswer()` (`gogemini/api.go`) ritorna `nil`, non accetta un prompt né restituisce una risposta.
- `getSnim0e()` e `restyPost()` non sono mai chiamate; il campo `sNlM0e` non viene mai scritto.
- `gogemini/response.go` è vuoto; `RequestGetAnswer` non è usata.
- Il README dice «A powerful Go package that returns response of Google Bard»: non è vero oggi.

### 3. [ALTO] Test assenti e `go test` rotto in locale

```
$ go test ./...
2026/09/29 14:05:32 Error loading .env file
FAIL	github.com/Allan-Nava/go-gemini/test
```

`TestMain` imposta `APP_ENV=test`, `env.Load()` cerca `../env/.env.test` (inesistente) e chiama
`log.Fatal`. In CI passa solo perché il workflow esporta `APP_ENV=runner`. Anche quando passa,
il risultato è `[no tests to run]`.

### 4. [ALTO] La libreria termina il processo del chiamante

- `configuration.GetConfiguration()` → `panic("failed to read configuration")`.
- `env.Load()` → `log.Fatal` con path relativi (`./env/...`, `../env/...`) che dipendono dalla
  directory corrente.
- `getSnim0e()` → `log.Println` della risposta intera.

Un SDK deve restituire `error` e lasciare al chiamante logging e caricamento `.env`. Proposta:
opzioni funzionali (`WithAPIKey`, `WithBaseURL`, `WithHTTPClient`, `WithModel`) come in
`MistServer-go-sdk`, e rimozione del package `env` dall'API pubblica.

### 5. [MEDIO] Client HTTP incoerente

- `Content-Type: application/x-www-form-urlencoded` impostato su **tutte** le richieste, mentre
  `restyPost` serializza un body JSON e chiede `Accept: application/json`.
- Header `Host` impostato a mano (lo gestisce `net/http`), User-Agent Chrome 91 falsificato.
- Nessun timeout: resty senza `SetTimeout` può restare appeso indefinitamente.
- Con `IS_DEBUG=true` resty stampa gli header, cookie inclusi: rischio di incollare il segreto in
  una issue.

### 6. [MEDIO] Dipendenze e toolchain vecchie — ✅ risolto (2026-09-29)

- `govulncheck`: 0 vulnerabilità raggiungibili dal codice, 20 nei moduli richiesti.
- `github.com/caarlos0/env/v6` e `godotenv` servono solo al caricamento `.env`: spariscono con le
  opzioni funzionali.

### 8. [MEDIO] Dockerfile inutilizzabile

Il repo è una libreria: `go build ./...` non produce `/app/main`, quindi `COPY --from=build /app/main`
fallisce. Da rimuovere (un SDK non si distribuisce come immagine).

  `go-bfard` (typo).
- README: «MIT License, Version 2.0» non esiste (il file `LICENSE` è MIT standard); link a

  visitatori a una property di terzi, e Universal Analytics è dismesso. **Rimosso** con il nuovo sito.
