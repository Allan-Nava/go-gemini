# CLAUDE.md — go-gemini

SDK Go (`github.com/Allan-Nava/go-gemini`, package `gogemini`) per l'**API ufficiale Gemini**: `gogemini.New(opts...)` → `Client.GenerateContent`, chiave nell'header `x-goog-api-key`. **Modulo senza dipendenze** (solo stdlib, `go.sum` vuoto). **Stato: v1.1.0 rilasciata (2026-09-30), API congelata dalla v1.0.0; prossima v1.2.0 (tool calling)** — ⛔ da qui niente cambiamenti incompatibili all'API esportata: `api-compat` in CI li blocca (base `v1.*`); si aggiunge soltanto; il vecchio client Bard (cookie `__Secure-1PSID` + token `SNlM0e`) è stato rimosso — breaking change, vedi `CHANGELOG.md`. Prova manuale: `go run ./examples/generate "…"` con `GEMINI_API_KEY`. Sito: GitHub Pages `https://allan-nava.github.io/go-gemini/` (HTML statico in `docs/`, deploy via `.github/workflows/pages.yml`). Contesto storico: `docs/audit-2026-09-29.md`.

## Regole di lavoro (SEMPRE)

- **MAI `git push`** — lo fa sempre l'utente, come tag e release. MAI `Co-Authored-By` né footer di attribuzione in commit/PR. Commit solo se richiesto.
- **Repo PUBBLICO**: prima di ogni commit `git grep` + `git log -p` per segreti e nomi interni. ⛔ Mai chiavi API o cookie Google in codice, test, esempi, file `.env*` (ignorati da git), log o issue. Esempi solo con placeholder (`YOUR_API_KEY`).
- **Verifica prima di dire "fatto"**: `gofmt -l .` (vuoto), `go vet ./...`, `go test -race ./...` (nessuna variabile d'ambiente), `go mod tidy -diff`, `go run honnef.co/go/tools/cmd/staticcheck@v0.8.1 ./...`, `go run golang.org/x/vuln/cmd/govulncheck@v1.8.0 ./...`, `golangci-lint run ./...` v2.14.0 (stesse versioni fissate in CI).
- **Documentare SEMPRE**: modifica all'API pubblica o all'autenticazione → `README.md` + `docs/index.html` (Quickstart e tabella API) + `CHANGELOG.md` (*Unreleased*, Keep a Changelog, in inglese) nello stesso commit. Lavoro pianificato → `docs/milestone.md` (non TODO sparsi nel codice). Audit/analisi → `docs/<tema>-<YYYY-MM-DD>.md` con schema ASCII.
- **Allineare tutto**: nome del progetto (go-gemini, non go-bard), variabili d'ambiente, modello di default, versione Go minima: `go.mod`, matrice CI, README, sito, CHANGELOG e CLAUDE.md devono dire la stessa cosa.
- **Direzione decisa (2026-09-29)**: API ufficiale Gemini (audit §1, opzione A). ⛔ Non reintrodurre lo scraping del web client (cookie, `SNlM0e`, `StreamGenerate`).
- ⛔ **Cancellazioni di file/package**: solo su richiesta esplicita dell'utente (il primo `git rm` dei package legacy è stato bloccato dai permessi finché l'utente non ha chiesto di chiudere la milestone). Mai aggirarle svuotando i file.

## Pattern per modifiche all'SDK

1. **Baseline**: build/vet/test prima di toccare nulla, per distinguere i fallimenti nuovi da quelli esistenti.
2. **Errori, non panic**: il codice di libreria ritorna `error` (sentinel esportati, `errors.Is`/`errors.As`); niente `panic`, `log.Fatal`, `log.Println` nei package importabili. ⛔ **Niente dipendenze nuove**: il modulo è solo stdlib; aggiungerne una va motivato e documentato.
3. **Test senza rete**: `httptest.Server` + `WithBaseURL`; nessun test deve chiamare Google. `Example…` in `_test.go` per ogni funzione pubblica (finisce su pkg.go.dev).
4. **Chiusura**: README + sito + CHANGELOG + milestone aggiornati, verifiche verdi, comandi di verifica nel messaggio all'utente.

## Trappole note / regole tecniche

- **Milestone GitHub = `docs/milestone.md`**: il workflow `milestone-sync.yml` (script `.github/scripts/milestone_sync.py`, solo stdlib) crea/aggiorna milestone e issue con label `milestone-sync` a ogni push su `main`; sulle PR fa solo `--check`. ⛔ Non modificare titolo/corpo di quelle issue su GitHub: il sync li sovrascrive. Per chiudere un item: `[x]` nel file (chiuderla solo su GitHub lascia un warning, il sync non la riapre); una milestone si chiude quando tutti i suoi item sono `[x]`. Ogni item vuole `<!-- id:… -->` univoco e **stabile** (rinominarlo = issue nuova + la vecchia chiusa *not planned*). Prima di applicare a mano: `python3 .github/scripts/milestone_sync.py --dry-run`. ⚠️ **Gli elenchi delle issue di GitHub sono in ritardo di qualche secondo sulle scritture, con o senza filtro per label**: due giri ravvicinati hanno creato duplicati due volte (#46–#47, poi #72–#76 il 2026-09-29). Lo script quindi, dopo l'elenco, legge per numero (`GET /issues/{n}`, sempre aggiornato) le issue oltre l'ultima elencata fino al primo 404 (410 = cancellata, si salta) e chiude i duplicati tenendo il più vecchio. Non rimuovere quel passaggio.
- **Sicurezza della chiave (audit v0.2.0 A1–A2)**: `net/http` ricopia gli header custom, `x-goog-api-key` compreso, su **qualsiasi** redirect — anche verso un altro host. Per questo `New` imposta `sameHostRedirect` sul client di default e su una **copia** di quello passato con `WithHTTPClient` se non ha `CheckRedirect` (mai modificare il client del chiamante). `WithBaseURL` accetta solo `https`, `http` solo per loopback. Test di regressione in `gogemini/hardening_test.go`: non indebolirli.
- ⛔ **Struct esportate confrontabili restano confrontabili** (`gorelease`, 2026-09-30): aggiungere un campo slice/map/func a `Client`, `PromptFeedback`, `Part`, `Blob`, `FileData`, `SafetySetting`… li rende non confrontabili con `==` = **incompatibile**. Sui campi privati si mette un puntatore (`Client.safetySettings *[]SafetySetting`); su quelli esportati si rinuncia al campo (per questo `PromptFeedback` non ha `SafetyRatings`). `Candidate`, `Content`, `Response`, `GenerationConfig`, `GenerateContentRequest` erano già non confrontabili. Prima di ogni commit che tocca l'API: `gorelease -base=<ultimo tag>` su un clone pulito.
- **Costanti che cambiano valore = incompatibili** per `apidiff`/`gorelease` (verificato 2026-09-29). Per questo `version`, `defaultModel` e `defaultTimeout` in `gogemini/client.go` **non sono esportate**: non riesportarle. Nuove costanti esportate solo se il valore è stabile per sempre (`DefaultBaseURL`, `APIKeyEnv`).
- **v1.1.0 (API ufficiale, verificata sul riferimento del 2026-09-30)**: output JSON via `responseFormat.text` (`mimeType` `APPLICATION_JSON` + `schema`), **non** `responseSchema`/`responseJsonSchema` (deprecati); `thinkingConfig` = `includeThoughts`/`thinkingBudget`/`thinkingLevel`; `countTokens` con `generateContentRequest` che richiede `model: "models/…"`. Il riassunto di WebFetch su quella pagina (1,2 MB) è inaffidabile: scaricarla con curl e cercare i nomi dei campi.
- **v1.2.0 tool calling (riferimento del 2026-09-30)**: `functionDeclarations[]` con `parametersJsonSchema` (non `parameters`, che è OpenAPI); `functionCall {id, name, args}`, `functionResponse {id, name, response}` — `response` deve essere un oggetto JSON (`asObject` avvolge il resto in `{"result": …}`). ⚠️ Il riferimento si contraddice sul `role` del contenuto con i risultati (`Tool`: "function"; `Content.role`: solo "user"/"model"): l'SDK usa **"user"**, da confermare con la prova reale (`examples/functions`). Il giro di `Chat.Send` è atomico: la storia si aggiorna solo a turno riuscito.
- ⚠️ **Timeout (v1.0.0)**: mai `http.Client.Timeout` sul client di default — comprende la lettura del body e taglia gli stream lunghi (riprodotto: 3 chunk su 6). Il limite è per tentativo, via context in `attempt()` (`generate.go`): `Generate` = richiesta + risposta intera, stream = solo fino agli header. Un tentativo scaduto si ritenta (`no reply within …`), la deadline del chiamante no. Nei test, un handler che aspetta la disconnessione deve **leggere prima il body** (`hang` in `timeout_test.go`), altrimenti il server non se ne accorge e `srv.Close()` resta appeso.
- **Rilascio**: `CHANGELOG.md` da *Unreleased* a `## [vX.Y.Z] — data` + `version` in `gogemini/client.go` = `X.Y.Z`, poi l'utente fa tag e push; il workflow `release.yml` verifica entrambi (`.github/scripts/release_notes.py vX.Y.Z --check`), rilancia i test e crea la release dalle note del changelog. La release v0.2.0 è stata creata a mano.
- **Lint**: `golangci-lint` v2.14.0 in CI (`.golangci.yml`: default + `bodyclose`, `errorlint`, `misspell`, `nilerr`, `noctx`; nei `_test.go` escluso solo `errcheck` su `io.WriteString`/`fmt.Fprint*` degli handler `httptest`). Aggiornamenti dipendenze: **solo Renovate** (Dependabot rimosso in v0.4.0).
- **Retry di default** (v0.4.0): 4 tentativi su 408/429/5xx ed errori di rete, mai su context/`ErrRedirectOtherHost`. Nei test il client di `newTestClient` ha `MaxAttempts: 1` e i test di retry usano `fastRetry` (ms): un test che crea un client con `gogemini.New` e riceve 429/5xx aspetta secondi veri. ⚠️ **Streaming**: su `break` chiudere il body **senza drenarlo** — `drainClose` su uno stream aperto blocca fino al timeout (60 s, trovato da `TestStreamBreakClosesConnection`).
- **Gate CI**: copertura `gogemini` ≥ 90%; `gorelease` contro l'ultimo tag, **bloccante** (base `v1.*`; con base `v0.*` era solo warning). ⚠️ Negli step con pipe usare `set -o pipefail` e scrivere i report in `$RUNNER_TEMP`, mai nel checkout: il 2026-09-29 `gorelease | tee gorelease.txt` è risultato verde senza aver girato (il file appena creato rendeva il repo "sporco" e `tee` nascondeva l'errore). E `gorelease` esce con 1 anche solo perché non può suggerire una versione (commit già taggato, proxy Go non ancora aggiornato: successo al push di `v0.3.0`): lo step decide dal **report** (`# summary` presente, sezione `## incompatible changes`), non dal codice di uscita, e su un commit taggato confronta con il tag precedente.
- **Client** (`gogemini/client.go`, `generate.go`): opzioni applicate in ordine, `WithAPIKey` batte `GEMINI_API_KEY`; `WithTimeout` (default 5 min) vale per tentativo anche con `WithHTTPClient`. Validazione in `New` (`ErrInvalidBaseURL`, `ErrInvalidTimeout`, `ErrEmptyModel`) e prima dell'invio (`ErrEmptyRequest`). Errori non-2xx → `*APIError` (body letto max 1 MiB, `Message` troncato a 1 KiB); risposte 2xx lette max 32 MiB e drenate per riusare la connessione. La chiave non deve mai finire in URL o messaggi d'errore: c'è un test che lo verifica. Modello di default `defaultModel` = `gemini-3.8-flash` (consigliato dai doc Google al 2026-09-29; la serie 2.5 ha accesso limitato) — se cambia: minor release, CHANGELOG, `TestDefaults`, README, sito.
- **Prove dal vivo contro Google**: solo su richiesta esplicita, una richiesta alla volta, mai in CI né nei test del repo. Con una chiave reale le lancia l'utente (`examples/generate`). Il vecchio endpoint web `StreamGenerate` risponde anche senza cookie (audit §0) e la risposta contiene la **località stimata dall'IP**: non salvarla in file tracciati, log o issue.
- ⚠️ **Script Python che riscrivono file**: mai `open(p, 'w').write(open(p).read())` — l'apertura in scrittura tronca il file prima della lettura. È successo a questo file il 2026-09-29 (commit `60f1640`, ripristinato prima del push).
- **Floor Go 1.26** (`go 1.26.0`): scelto con l'aggiornamento di `x/net` e mantenuto dopo la rimozione di tutte le dipendenze (versioni supportate: 1.26, 1.27). Matrice CI = floor + `stable`; se alzi il floor aggiorna `go.mod`, entrambi i workflow, README e `docs/index.html` (Quickstart).
- **GitHub Pages**: build type *workflow*, pubblica `./docs` così com'è (`.nojekyll`, nessun Jekyll). I `.md` in `docs/` si leggono su GitHub, non come pagine del sito: linkarli con URL `github.com/.../blob/main/docs/...`.
